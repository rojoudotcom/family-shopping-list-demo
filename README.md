# 家族の買い物リスト

研修用に作った架空のデモアプリです。家族それぞれが買うものを書き足し、買ったらチェックを付けます。
素の HTML・CSS・JavaScript だけで作っています（フレームワーク・ビルド工程なし）。

## アプリの機能

- 品物の追加・削除
- 「買った」のチェック
- 「すべて／まだ買っていない／買った」での絞り込み
- 「あと N 品」の表示
- ブラウザの `localStorage` への保存（リロードしても残る）

機能はわざと最小限にしてあります。新しい機能は、研修の中で PRD から追加します。

## このリポジトリで実演すること

3つの役割が、それぞれの文書を AI と作り、次の役割に渡します。各段階の指示は `.github/prompts/`、文書の形は `docs/templates/` にあります。

| 役割                 | 段階                                                                                 | 呼び出し                 | 置き場                               |
| -------------------- | ------------------------------------------------------------------------------------ | ------------------------ | ------------------------------------ |
| 営業・サポート担当者 | 利用者の情報と過去の記録から、ヒアリングのアジェンダを作る                           | `/agenda`                | `docs/hearing/`                      |
|                      | ヒアリングの文字起こしから議事録を作る                                               | `/minutes`               | `docs/minutes/`                      |
| 企画担当者           | 議事録と問い合わせの記録から、PRD を GitHub の Issue として書く                      | github.com の Copilot    | GitHub の Issue（Project に載せる）  |
| エンジニア           | PRD から要件定義書と設計書（ユースケース図・アーキテクチャ図・ERD つき）を一度に作る | `/spec`                  | `docs/requirements/`・`docs/design/` |
|                      | 設計書のタスクから Issue を作る                                                      | `/issues`                | GitHub の Issue（Project に載せる）  |
|                      | Issue を Copilot に任せ、PR・CI・レビューを経てマージする                            | Issue の担当者に Copilot | `main`                               |

PRD とチケットの Issue は、リポジトリのかんばんの GitHub Project「家族の買い物リスト」に載せ、進み具合を見ます。
要件定義書だけ、設計書だけを書き直すときは、`/requirements`・`/design` を使います。
要件定義書と設計書は `docs/` のファイルのままにし、PRD の Issue とチケットの「関連」からリンクします。

`main` にマージすると GitHub Pages に公開され、PR の説明の `Fixes #番号` で Issue が閉じます。

## ディレクトリ構成

```
index.html                  画面（src/app.js を ES モジュールとして読み込む）
src/
  listStore.js              DOM に依存しない純粋関数（ユニットテストの対象）
  app.js                    DOM の配線と localStorage への保存
  styles.css                スタイル
scripts/serve.mjs           依存ゼロの静的サーバ（ローカル確認用）
test/unit/listStore.test.js ユニットテスト（node:test）
.github/workflows/
  ci.yml                    CI: Lint とユニットテスト（PR ごとに実行）
  deploy.yml                CD: main への push で GitHub Pages に公開
```

品物を扱うロジックは `listStore.js` に純粋関数として置き、DOM から切り離しています。
そのため、ユニットテストはブラウザを起動せずにミリ秒で終わります。

## ローカルでの実行

Node.js 20 以上が必要です。

```bash
npm ci               # 依存パッケージを導入する（初回のみ）
npm run serve        # http://localhost:4173 を開く
npm test             # ユニットテスト（node:test）
npm run lint         # ESLint と Prettier のチェック
```

Lint で整形の指摘が出たら、`npm run format` で自動修正できます。

## 企画のワークベンチ（エンジニアでない人向けの画面）

アプリを作るチームの社内の画面です。VS Code を開かずに、ブラウザから AI に文書を書かせます。画面は2つあります。

| 画面            | 使う人               | できること                                                                                                      |
| --------------- | -------------------- | --------------------------------------------------------------------------------------------------------------- |
| 顧客管理（CRM） | 営業・サポート担当者 | ①ヒアリングのアジェンダを作る ②録音を文字起こしする ③文字起こしから議事録を作る ④文字起こしを顧客管理に登録する |
| 文書ツール      | 企画担当者           | 議事録と、顧客管理に登録されたお客さんの声から PRD の下書きを作り、決まっていないことに答える                   |

```bash
npm run workbench    # http://127.0.0.1:4174 を開く（このパソコンからだけ開ける）
```

- AI が書いた文書は、このリポジトリの `docs/` にファイルとして保存されます。データベースは使いません。
- 顧客管理の中身は `docs/crm/お客さんの声.json`（記録の配列）です。最初に、問い合わせ記録の5件を入れてあります。
  ④では、AI が文字起こしから1件の記録を書き、画面の裏のサーバが形と「そのままの言葉」が文字起こしにあるかを確かめてから、このファイルに足します。
- AI は GitHub Copilot です。画面の裏で Copilot CLI を呼び、VS Code の `/agenda`・`/minutes`・`/prd` と同じ
  `.github/prompts/` の指示を渡します（④は `crm.prompt.md`）。Copilot CLI を入れてサインインしておく必要があり、AI への問い合わせはネットワーク越しに行われます。
  `copilot` が PATH に無いときは、環境変数 `COPILOT_BIN` で場所を指定します。
- 文字起こしは、このデモでは擬似です。`audio/<名前>.m4a` を選ぶと、用意しておいた
  `docs/hearing/<名前>_文字起こし.txt` を数秒待ってから表示します。
- Copilot には `git push`・`git commit`・`gh` を禁止しています。コミットと push は人が行います。

## 社内の管理画面のモックアップ（デモ用）

営業・サポート担当者、企画担当者、QA が使う社内の画面を、動かない見本（モックアップ）として `mock/` に置いています。
研修のデモで、エンジニアでない人の仕事を画面で見せるためのものです。

```bash
npm run serve        # http://localhost:4173/mock/ を開く（末尾の「/」まで入れる）
```

| タブ            | 使う人               | 見せること                                                                                  |
| --------------- | -------------------- | ------------------------------------------------------------------------------------------- |
| 顧客管理（CRM） | 営業・サポート担当者 | お客さん・問い合わせ5件・ヒアリング2回目（録音 → 文字起こし → 議事録）・お客さんの声        |
| PRD             | 企画担当者           | 小さな機能の PRD（受け入れ条件 AC-01〜03）・元にした資料・次に作るものの投票・Issue #8      |
| QA の確認       | QA                   | 受け入れ条件ごとの前提・操作・結果、テストの結果、画面での確かめ、PR に貼るコメントのコピー |

- 擬似のもの：「AI に議事録を作らせる」「AI に下書きさせる」は、2秒待ってから用意しておいた文書を見せるだけです。AI は呼びません。投票の結果と、テストの ✓ も擬似です。データベースは使いません。
- 本物のもの：「QA の確認」の「画面で確かめる」は、アプリと同じ `src/listStore.js` の `addItem` で行を足します。機能の PR をマージする前は main の動き（同じ名前でも行が増える）、マージした後は新しい動きになります。
