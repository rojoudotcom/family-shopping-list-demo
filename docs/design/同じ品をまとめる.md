# 設計書：同じ品物を1行にまとめる

元の要件定義書：docs/requirements/同じ品をまとめる.md

## 1. 解決したい課題・概要

同じ品物がリストに2行できて、家族が同じ物を二度買ってしまう。
品物を足すとき、大文字小文字と前後の空白の違いを無視して、すでにある品物と同じかを調べ、同じなら行を増やさない。
チェック済みの同じ品物を足したときは、その行を「まだ買っていない」状態に戻す。あわせて、チェックを付けた行をリストの末尾に移す。

## 2. 技術の前提

- 言語：素の HTML・CSS・JavaScript（ES モジュール、フレームワークなし）
- 保存先：ブラウザの `localStorage`（キー `family-shopping-list-items`、既存のまま）
- 動く環境：ブラウザ（GitHub Pages で公開）。ロジックは `src/listStore.js` の純粋関数に置き、node:test で確かめる

## 3. 変えるところ

- `src/listStore.js` の `addItem`：前後の空白を除いた品名を、大文字小文字を無視して `items` の各 `name` と比べる（ひらがな／カタカナ、全角／半角は区別したまま）。
  - 空の品名は、これまでどおり「品名を入力してください」で拒否する
  - 同じ品物がなければ、これまでどおり末尾に新しい行を足す
  - 同じ品物があり `bought` が false なら、`items` をそのまま返す
  - 同じ品物があり `bought` が true なら、その行だけ `bought` を false にした新しい配列を返す（行の位置は、5章の未決定事項が決まるまで動かさない）
- `src/listStore.js` の `toggleBought`：チェックを付けるとき（`bought` が false → true）、その行を配列の末尾へ移す。チェックを外すときの位置は、5章の未決定事項が決まるまで変えない。
- `src/app.js`：変更なし。`submit` ハンドラは `addItem` の戻り値を `update` に渡すだけで、同じ品物でもメッセージを出さず、再描画と `save()` が走る。`addItem` が例外を投げるのは空の品名のときだけで、その動きは変わらない。
- `test/unit/listStore.test.js`：上の2関数のテストを足す。
- `README.md` の機能一覧：「同じ品物は1行にまとめる」「チェックを付けた品物は末尾に移る」を足す。

## 4. データの形

変更なし。品＝`{ id: number, name: string, bought: boolean }`。
`localStorage` には、この配列を JSON のまま保存する。すでに別の行になっている同じ品物は、そのまま残る。

## 5. エラーとイレギュラー

- 空の品名：これまでどおり「品名を入力してください」を表示して拒否する
- 全角・半角、ひらがな・カタカナの違い：別の品物として扱う（対象外）
- すでに2行以上ある同じ品物：まとめない。新しく足すときは、先に見つかった行を同じ品物として扱う
- 間違えて戻した行：もう一度チェックを付ければ、末尾へ移る
- 決まっていないこと（要件定義書8章）。推測で決めず、人に尋ねる：
  - [ ] チェックを外した行を、リストのどこに置くか（A. 末尾に残す／B. まだ買っていない物の並びの末尾／C. チェックを付ける前の位置）。決まるまで、位置は動かさない実装にしておく
  - [ ] 同じ品物を足したときにメッセージを出さないこと（FR-05）でよいか。企画担当者に確認する
  - [ ] 買った物を末尾に移すこと（FR-04）の根拠となる Zoom の投票結果の記録

## 6. テスト観点

- AC-01：`addItem([牛乳], '牛乳')` の長さが1のまま
- AC-02：`addItem([Milk], 'milk')` の長さが1のまま
- AC-03：`addItem([牛乳], '牛乳 ')` の長さが1のまま
- AC-04：`addItem([牛乳], ' 牛乳')` の長さが1のまま
- AC-05：`addItem([卵（bought: true）], '卵')` の長さが1のままで、その行の `bought` が false
- AC-06：AC-05 の結果を `countToBuy` に渡すと、渡す前より1大きい
- AC-07：`addItem([], 'パン')` の長さが1になり、`bought` が false の新しい行がある
- AC-08：`toggleBought` でチェックを付けた行が、配列の末尾にある（先頭・途中の行で確かめる）
- AC-09：同じ品物を足しても `addItem` は例外を投げず、メッセージ用の値を返さない（配列だけを返す）。画面では `#form-error` が空のまま
- AC-10：同じ品物を足した結果を `JSON.stringify`／`JSON.parse` で往復しても、行が1つで `bought` の状態が同じ
- 既存の機能：既存の `listStore.test.js` と `workbench.test.js` が通り（`npm test`）、`npm run lint` も通る。空の品名の拒否、`deleteItem`、`filterItems`、`countToBuy` の既存テストが変わらず通る
