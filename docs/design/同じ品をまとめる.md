# 設計書：同じ品目を1行にまとめる

元の要件定義書：docs/requirements/同じ品をまとめる.md

## 1. 解決したい課題・概要

今は同じ品目を足すと、大文字・小文字や前後の空白が違うだけで、あるいはチェック済みの品目でも、新しい行が増える。そのため同じ物を2回買ってしまう。
品目を足すとき、すでにある品目と同じなら行を増やさず、チェック済みなら前からある行を「まだ買っていない」に戻す。あわせて、チェックを付けた品目はリストの末尾に移す。

## 2. 技術の前提

- 言語：素の HTML・CSS・JavaScript（ES モジュール）。フレームワークとビルド工程は足さない
- 保存先：ブラウザの `localStorage`（キー `family-shopping-list-items`、今までどおり）
- 動く環境：ブラウザ。GitHub Pages で公開
- テスト：`test/unit/` に node:test のユニットテスト。`npm test` と `npm run lint` を通す

## 3. 変えるところ

- `src/listStore.js` の `addItem`
  - 前後の空白を除いた名前を小文字にして比べ、すでにある品目と同じなら、新しい行は足さない（FR-01）
  - 同じ品目の行が `bought: true` なら `bought: false` にする（FR-02）。その行の id と名前は前からあるまま変えない
  - 同じ品目がなければ、今までどおり末尾に新しい行を足す（FR-04）
  - 空白だけの入力は、今までどおり「品名を入力してください」で拒否する
  - 比べるときの正規化は、`src/listStore.js` の内部関数（例：`normalizeName`）に置く。`trim` と `toLowerCase` だけを使い、全角・半角やひらがな・カタカナの変換はしない
- `src/listStore.js` の `toggleBought`
  - チェックを付けた（`bought` が `true` になった）品目を、配列の末尾に移す（FR-03）
  - チェックを外す場合の動作は変えない（位置は動かさない）
- `src/listStore.js` の `filterItems`、`countToBuy`、`deleteItem` は変えない。「あと N 品」は `countToBuy` が数えるので、AC-06 は `addItem` の変更だけで満たされる
- `src/app.js` はロジックを変えない。`form` の `submit` ハンドラの `addItem` 呼び出し、`checkbox` の `change` ハンドラの `toggleBought` 呼び出し、`update` と `render` は、そのまま新しい配列を描画する。`submit` ハンドラのコメント（「空白の除去・空文字の拒否」）だけ、同じ品目のまとめも `addItem` が行うことが分かるように直す
- `test/unit/listStore.test.js` に、`addItem` と `toggleBought` のテストを足す

## 4. データの形

変えない。品＝`{ id: number, name: string, bought: boolean }`。

- `id`：「現在の最大 id + 1」のまま。まとめた行の id は変わらない
- `name`：前からある行の表記のまま（「milk」の行に「Milk」を足しても「milk」のまま。要確認：5 の1つ目）
- `bought`：チェック済みの品目を足し直すと `false` に戻る
- 並び：配列の順がそのまま表示順。チェックを付けた品目は配列の末尾に移る
- 保存の形（`localStorage` の JSON）は今までと同じなので、保存データの移行は要らない

## 5. エラーとイレギュラー

- 空白だけの入力：今までどおり「品名を入力してください」を出して拒否する。保存データは変わらない
- 間違えて戻した行：チェックはもう一度付ければ、買った状態に戻せる。間違えて足した品は、今までどおり「削除」で消せる
- 全角と半角（「ＭＩＬＫ」と「MILK」）、ひらがな・カタカナ・漢字の違いは、別の品目のままにする（対象外）
- 行が増えないとき画面で知らせることは、作らない（対象外）
- 家族の端末どうしで同じリストを見る仕組みは、作らない（対象外）
- 要確認（要件定義書の「決まっていないこと」。人に尋ねる。答えが出るまで、設計は次の仮の動作にしてある）
  - 「Milk」を足して「milk」にまとめるとき、表示名は前からある表記のままでよいか（仮：前からある表記のまま）
  - 品目の途中の空白（「牛乳 パック」と「牛乳 パック」）は同じ品目にするか（仮：まとめない。前後の空白だけを除く）
  - 保存データにすでにある2行の同じ品目は、まとめ直すか（仮：そのまま。読み込み時には手を入れない）
  - 「すべて／まだ買っていない／買った」の絞り込みのとき、「リストの末尾」はどう見えればよいか（仮：「すべて」のときだけ、買った品目が末尾に並ぶ）
  - 買った品目が複数あるときの末尾の並び順（仮：チェックを付けた順）
  - チェックを外した品目をどこに置くか（仮：今の位置のまま動かさない）

## 6. テスト観点

- AC-01：`addItem` に `[{id:1, name:'milk', bought:false}]` と `'Milk'` を渡し、返る配列の長さが1のままであることを確かめる
- AC-02：`addItem` に「牛乳」の入った配列と `'牛乳 '` を渡し、返る配列の長さが1のままであることを確かめる
- AC-03：`addItem` に「牛乳」の入った配列と `' 牛乳'` を渡し、返る配列の長さが1のままであることを確かめる
- AC-04：`addItem` に、まだ買っていない「牛乳」の入った配列と `'牛乳'` を渡し、返る配列の長さが1のままであることを確かめる
- AC-05：`addItem` に、`bought: true` の「卵」の入った配列と `'卵'` を渡し、行が増えず、その行の `bought` が `false` になることを確かめる
- AC-06：AC-05 の結果に `countToBuy` を使い、足す前より1つ増えることを確かめる
- AC-07：「牛乳」「パン」の入った配列で `toggleBought` を「牛乳」の id に使い、返る配列の最後が「牛乳」で `bought` が `true` になることを確かめる
- AC-08：空の配列、および「パン」だけの配列に、`addItem` で「牛乳」と「卵」を足し、それぞれ別の行になることを確かめる
- 既存の機能：既存のテストをすべて通し（`npm test`）、`npm run lint` を通す。空白だけの入力の拒否と、入力を書き換えない（イミュータブル）ことの既存テストも含めて確かめる
