# 設計書：同じ品をまとめる

元の要件定義書：docs/requirements/同じ品をまとめる.md

## 1. 解決したい課題・概要

同じ品目が大文字小文字や前後の空白の違いで2行になり、2回買いが起きている。
品目を足すとき、すでにある同じ品目に行をまとめ、チェック済みなら「まだ買っていない」に戻す。
また、チェックを付けた品目はリストの末尾へ移す。

## 2. 技術の前提

- 言語：HTML と JavaScript（フレームワーク・ビルド工程なし）
- 保存先：ブラウザの `localStorage`（キー `family-shopping-list-items`。今のまま）
- 環境：ブラウザ。ロジックは `src/listStore.js` の純粋関数で、ブラウザなしに `npm test`（node:test）で確かめる
- 公開：GitHub Pages（今のまま）

## 3. 変えるところ

- `src/listStore.js` の `addItem`
  - 前後の空白を除いた名前を、大文字小文字を区別せずに（`toLowerCase()` で）既存の品目の `name` と比べる
  - 一致する品目がない → 今まで通り新しい行を末尾に足す（FR-05）
  - 一致し、`bought` が `true` → 新しい行は足さず、その行の `bought` を `false` にする。行の `id` と `name` は変えない（FR-03）
  - 一致し、`bought` が `false` → 配列を変えずに返す（FR-01, 02, 04）
  - 空の名前を拒否する今の動きと、引数を書き換えない性質は保つ
- `src/listStore.js` の `toggleBought`
  - `bought` が `false` から `true` になる品目を、配列の末尾へ移す（FR-06）
  - `true` から `false` に戻すときの動きは今のまま（その場で反転）
- `src/app.js`：変更なし。`submit` の処理は `addItem` の戻り値を `update` に渡し、チェックの `change` は `toggleBought` の戻り値を `update` に渡しているため、返ってくる配列が変われば画面にも反映される
- `test/unit/listStore.test.js`：`addItem`・`toggleBought` のテストを足す。末尾へ移す変更で、既存の `toggleBought: 指定した id の品物だけ「買った」を反転する` は並びが変わるため、期待値を直す
- `README.md`：「アプリの機能」に「同じ品目は1行にまとめる」「買った品目は末尾へ移る」を1行ずつ足す

## 4. データの形

変更なし。品＝`{ id: number, name: string, bought: boolean }`。
`localStorage` に保存している配列の形も同じで、今ある保存データはそのまま読める。

## 5. エラーとイレギュラー

- すでに2行になっている品目は、そのままにする。利用者が「削除」で消して直す（対象外）
- 「卵」と「たまご」は別の品目として扱う（対象外：読みや表記の違いは同じ品目にしない）
- 空の名前は、今まで通り「品名を入力してください」で拒否する
- 間違えて足した品目は、「削除」で消せる

決まっていないこと（要件定義書の「8. 決まっていないこと」より。人に確かめるまで、下のとおり今の動きのままにして作る）：

- まとめた行に表示する名前は、前からある名前のままでよいか。（今は前からある名前のまま）
- 途中の空白、全角の空白、全角の英字を同じ品目として扱うか。（今は扱わない。`trim()` で除ける前後の空白と、大文字小文字だけを同じとみなす）
- チェックを外した品目を、元の位置へ戻すか、今の位置のままか。「まだ買っていない」に戻した行（AC-04）はどこに表示するか。（今はどちらも今の位置のまま）
- チェックを付けた品目が複数あるとき、末尾での並び順はどうするか。（今はチェックを付けた順）
- 絞り込み中に同じ品目を足したとき、行が増えないことを画面でどう知らせるか。（今は知らせない。決まったら別の Issue にする）

## 6. テスト観点

- AC-01：`addItem([milk], 'Milk')` の結果の行数が1のまま
- AC-02：`addItem([牛乳], '牛乳 ')` の結果の行数が1のまま
- AC-03：`addItem([牛乳], ' 牛乳')` の結果の行数が1のまま
- AC-04：`addItem([チェック済みの卵], '卵')` の結果の行数が1のままで、その行の `bought` が `false`、`id` が元のまま
- AC-05：`addItem([チェックのない牛乳], '牛乳')` の結果の行数が1のままで、`bought` が `false` のまま
- AC-06：`addItem([牛乳], '卵')` の結果が2行で、末尾が「卵」（`bought` が `false`）
- AC-07：`toggleBought([牛乳, パン], 牛乳の id)` の結果で、「牛乳」が末尾にあり `bought` が `true`
- 既存の機能：既存の `listStore.test.js` のテスト（空の名前の拒否、`id` が最大値＋1、`deleteItem`、`filterItems`、`countToBuy`、引数を書き換えない）が通り、`npm test` と `npm run lint` が通る
