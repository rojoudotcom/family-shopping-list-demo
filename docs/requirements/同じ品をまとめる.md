# 要件定義書：同じ品物を1行にまとめる

元の PRD：docs/prd/同じ品をまとめる.md

## 1. 目的

同じ品物がリストに2行できて、家族が同じ物を二度買ってしまう。同じ品物を二度入れても1行のままにして、二重買いを防ぐ。

## 2. 使う人と場面

家族で買い物をする会員として、同じ品物をリストに二度入れても1行のままにしたい。それは、同じ物を二度買ってしまうのを防ぐためだ

## 3. 機能要件

- FR-01 品物を追加するとき、大文字と小文字の違い、前後の空白の違いを無視して、すでにある品物と同じかどうかを調べる
- FR-02 すでにある品物と同じなら、新しい行を作らない
- FR-03 同じ品物の行にチェックが付いているときは、新しい行を作らず、その行を「まだ買っていない」状態に戻す
- FR-04 品物にチェックを付けると、その行をリストの末尾に移す
- FR-05 同じ品物を足したときは、メッセージを出さず、行を増やさないだけにする
- FR-06 リストにない品物を足すと、これまでどおり新しい行が1つ増える

## 4. 受け入れ条件

- AC-01 前提 「牛乳」がすでにあるリスト／操作 「牛乳」を足す／結果 行は増えない
- AC-02 前提 「Milk」がすでにあるリスト／操作 「milk」を足す／結果 行は増えない
- AC-03 前提 「牛乳」がすでにあるリスト／操作 末尾に空白を付けた「牛乳 」を足す／結果 行は増えない
- AC-04 前提 「牛乳」がすでにあるリスト／操作 先頭に空白を付けた「 牛乳」を足す／結果 行は増えない
- AC-05 前提 チェックが付いた「卵」がある／操作 「卵」を足す／結果 行は増えず、その「卵」のチェックが外れる
- AC-06 前提 チェックが付いた「卵」がある／操作 「卵」を足す／結果 「あと N 品」の数が1つ増える
- AC-07 前提 リストに「パン」がない／操作 「パン」を足す／結果 新しい行が1つ増える
- AC-08 前提 チェックの付いていない品物がある／操作 その品物にチェックを付ける／結果 その行がリストの末尾に移る
- AC-09 前提 「牛乳」がすでにあるリスト／操作 「牛乳」を足す／結果 「すでにあります」などのメッセージは出ない
- AC-10 前提 「牛乳」がすでにあるリストに「牛乳」を足した／操作 ブラウザを再読み込みする／結果 行は1つのままで、チェックの状態も保たれている

## 5. 例外と境目

- 「Milk」と「milk」は同じ品として扱う（FR-01）
- 「牛乳」と、前後に空白が付いた「牛乳 」「 牛乳」は同じ品として扱う（FR-01）
- ひらがなとカタカナ、全角と半角の違いは、同じ品として扱わない（7章の対象外）
- 現在の実装では、空の品名は「品名を入力してください」と表示して拒否している。この動きは変えない
- すでに別の行になっている同じ品物は、そのまま残る（7章の対象外）

## 6. 非機能要件

- ブラウザで開ける（現在のアプリと同じ、素の HTML・CSS・JavaScript のまま）
- リストの状態はブラウザの `localStorage` に保存し、再読み込みしても残る（AC-10）
- 同じ品物かどうかの判定は `src/listStore.js` の純粋関数に置き、ユニットテストで確かめられる

## 7. 前提と対象外

前提

- 追加・チェック・削除・絞り込み・「あと N 品」の表示は、すでにある機能として使う

対象外（今回は作らない）

- ひらがなとカタカナ、全角と半角の違いを、同じ品物として扱うこと
- すでに別の行になっている品物を、あとから1行にまとめること
- 家族の端末どうしで同じリストを見る仕組み（次の段階にする）

## 8. 決まっていないこと

- [ ] チェックを外した（まだ買っていない状態に戻した）行を、リストのどこに置くか（選択肢：A. 末尾に残す／B. まだ買っていない物の並びの末尾に出す／C. チェックを付ける前の位置に戻す）。AC-05 の「チェックが外れる」行の位置は、これが決まるまで定まらない
- [ ] 「同じ品物を足したときはメッセージを出さない」（FR-05）は、PRD に理由の記載がない。この扱いでよいか、企画担当者に確認する
- [ ] 「買った物は末尾に移す」（FR-04）は、PRD では Zoom の投票で決まったとだけ書かれている。結果の記録が PRD に無いため、確認する
